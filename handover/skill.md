# 交接 Skill

## 触发条件

- 用户说 `/handover`、"交接"、"换窗口"、"上下文快满了"
- 会话中主动判断：当本轮对话已经历了多轮工具调用（超过 100 轮）且用户表现出对效率的关注（如"怎么这么久"、"效率变低了"）

## 执行步骤

### 第一步：停止所有后台任务

```
检查并停止所有正在运行的 Agent、后台命令、演示服务器等。
不要杀用户的游戏客户端。
```

### 第二步：写交接报告

写入 `D:\zhoform\重构产出\00-交接报告-YYYYMMDD.md`，必须包含：

1. **项目一句话**：什么项目、当前什么阶段
2. **已完成**：表格形式，每项附关键数字和验证方式
3. **今天解决的问题**：现象→根因→修复，附代码位置
4. **当前卡住的**：按优先级排列（P0/P1/P2...），附已定方案和临时绕行
5. **关键路径与资产**：所有重要文件/目录的位置和说明
6. **环境陷阱**：血泪经验（网络劫持、编码、杀进程等），逐条列出
7. **用户偏好与沟通**：语言、授权程度、汇报习惯、产品态度
8. **下一步**：新窗口的优先级行动清单

### 第三步：更新项目记忆

写入 `C:\Users\Lizhuo4\.claude\projects\D--zhoform\memory\chosen-rebuild-project.md`：
- 压缩为 <150 行（记忆是索引不是正文）
- 核心结构：项目定义→关键资产→当前进度→修复记录→环境陷阱→用户偏好
- 确保 MEMORY.md 索引行指向正确

### 第四步：写交接提示词

写入 `D:\zhoform\下一窗口提示词.md`：
- 开头一段话说明项目和当前阶段
- 指向交接报告和记忆文件的路径
- 核心路径速查表
- 新窗口的立即任务（按序）
- 最重要的 3-5 条环境陷阱（完整版见报告）
- 用户偏好摘要

### 第五步：告知用户

回复用户：
```
交接完成。产出三份文件：
1. [交接报告](路径) — 全部进度/问题/陷阱/下一步
2. [项目记忆](路径) — 已更新（新窗口自动读取）
3. [下一窗口提示词](路径) — 新窗口开场白

开新窗口后，把提示词文件的内容发给新对话即可。项目记忆会被自动加载。
```

## 注意事项

- 交接报告要**详尽**（新窗口没有本轮对话的上下文），但记忆文件要**精炼**（索引性质）
- 环境陷阱是最高价值的信息——新窗口不踩坑能省大量时间
- 用户偏好里关于产品态度（如反作弊立场）必须记录，避免新窗口做出错误判断
- 如果有正在进行但未完成的代码修改，在报告里标注文件名和改动位置
